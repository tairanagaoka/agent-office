## 1. 概要

Claude Code の複数エージェントを「平成レトロなドット絵オフィス」として可視化・
操作する、常駐型のローカルWebアプリ。

作者にとっての「作業母艦（司令室）」であり、ここを開けば1日の作業が回る状態を目指す。

## 2. 目的

| 区分 | 内容 |
|---|---|
| 根本動機 | 今後AI駆動開発をしていく上で、チャット形式だけでは飽きる。楽しんで使い続けられるAIツールを自分で作りたい |
| 実用目的 | エージェント分けと作業状況を可視化し、①誰に何を頼むべきか ②何がどこまで進んでいるか を分かりやすくする |

## 4. 構造

### 4-1 部屋（部署）と社員（エージェント）の2階層

```
オフィス
├─ 社長室          ← ユーザー自身の席
├─ 秘書室          ← 秘書エージェント（要件を聞いて振り分ける）
├─ 開発室
│   ├─ 実装担当
│   ├─ テスト担当
│   └─ レビュー担当
├─ 総務部          ← 生活サポート
├─ 経理部          ← 家計（※投資助言を想起させる「FP」は使わない）
└─ 書斎            ← ナレッジ蓄積
```

部屋をクリック＝そのエージェントと話す。ドット絵は装飾ではなくナビゲーションUI。
ユーザーは社員ではなく所長。自分の席を持つ。
エージェント定義は Markdown ファイルで外出しし、差し替え可能にする。

## 5. 機能（確定分）

### 5-1 Todo 管理と割り振り【中核】

```
Todo（今日やること）
  ├─ 自分でやる  → チェックするだけ
  └─ AIに振る    → 部署へ割り当て → タスク化 → 実行
```

Todo がタスクの供給源になる。

**追記（2026-08-22実装）**: Google Tasksとの連携を追加。Google Tasks→agent-officeの
一方向取り込みのみ（完了・削除の逆反映はしない）。同じGoogleアカウントの未完了タスクを
Todo一覧に取り込んで、そこからAIに振れる。詳細はCLAUDE.md・READMEを参照。

### 5-2 並行実行と進捗管理【中核】

複数エージェントを同時に走らせる。
「誰が」「何を」「どこまで」を常時表示（実行中／待機／完了／失敗）。
オフィスの見た目がそのまま進捗表示になる
（社員が動いていれば作業中、席にいなければ手が空いている）。

### 5-3 ダッシュボード

**全部署で共通に意味を持つ指標のみを出す。部署固有の指標は出さない。**

- トークン使用量・概算コスト（全体／エージェント別）
- 待ち時間（AIが考えている時間の累計）
- 稼働状況（実行中／待機中）
- タスク件数（進行中／完了／失敗）

### 5-4 書斎（ナレッジ蓄積）

エージェントが調べたこと、決めたこと、得た知見が溜まる場所。
セッションは消えるが書斎には残る。

### 5-5 場（世界観）

平成レトロのドット絵オフィス（ブラウン管、島型デスク、給湯室）。
オフィスのアンビエント音（遠くのキーボード、空調、電話、コピー機）
※効果音ではなく環境音として設計。目を離していても効く要素。

## 7. 技術構成

```
ブラウザ (React + TypeScript + Vite + ドット絵描画)
    │  POST /chat（送信） / GET /stream SSE（受信）
    ↓
Node.js + Hono (TypeScript)
    └ @anthropic-ai/claude-agent-sdk
         └ 各専門エージェント（Markdown定義を読み込み）
```

### 選定理由・制約

- **@anthropic-ai/claude-agent-sdk** … Claude Code をライブラリ化したもの。
  組み込みツール（Read/Write/Edit/Bash/Glob/Grep/WebSearch/WebFetch）、
  サブエージェント、フック、権限制御、セッション管理を持つ。
  SDKから流れるメッセージをそのまま部屋とアニメーションに変換できるため、
  別途フックを仕込む必要がない。
- **JS/TypeScript 中心であること** … 作者がJS/TSを学習したいという明確な意図がある。
  この制約は優先度が高い。
- **ローカルサーバー + ブラウザ表示** … デスクトップアプリ化しないことで
  ビルド・署名・配布の手間を回避。
- ドット絵描画ライブラリ（Phaser 等）の要否は未定。
  ゲーム性が低いため、CSS＋スプライトで足りる可能性がある。

## 8. 配布方針

**「公開」＝ 配布であって、ホスティングではない。** 各自のPCで動くローカルアプリを
GitHub / npm で配る（Claude Code や Jupyter と同じモデル）。

```
リポジトリ/
├─ templates/          ← 同梱するひな形（更新で上書きされる）
│   ├─ agents/*.md
│   └─ rooms.yaml
├─ server/             ← Node + Hono + Agent SDK
├─ web/                ← React + Vite
└─ docs/
```

実体は `~/.heisei-office/` にコピーする。
**更新時にユーザーが育てたエージェント定義を上書きしないこと。**

### セキュリティ要件（配布物として必須）

1. **localhost にバインドを固定**（0.0.0.0 にしない。同一ネットワークから触られる）
2. **Origin検証 ＋ 起動時発行のワンタイムトークン**
   （悪意あるWebページからの localhost へのPOSTを防ぐ。Jupyterと同方式）
3. **エージェントごとにツール権限を制限** ✅2026-08-22実装
   （SDKはBashとWriteが使える。無制限の任意コード実行は事故のもと）
   - 生活サポート・家計 … Read / WebSearch のみ
   - 開発 … 作業ディレクトリを限定、または承認を挟む
   - 実装: `templates/agents/*.md`のfrontmatterに`tools:`で許可ツールを宣言し、
     サーバー側でSDKの全ツール一覧から明示的に許可されたもの以外を`disallowedTools`で
     機械的に塞ぐ（許可リスト方式）。**`Task`（サブエージェント起動）も対象に含める**こと
     — 塞がないと「制限のゆるいサブエージェントに委任してBash等を回避する」抜け道が
     実際に発生した（M3〜M6の動作確認中に発見）。開発エージェントは`cwd`をプロジェクト
     ルートに固定。

### 公開時に必要なもの

- LICENSE（MIT想定）
- **ドット絵アセットは CC0 推奨**。NOTICE に出典明記（配布は自分用より条件が厳しい）
- 免責（AI出力の正確性、家計エージェントは投資助言ではない旨）
- 認証は各ユーザー自身の資格情報を使う。**開発者のAPIキーは同梱しない**

### 9-3 進め方の原則

1. **M2 到達時点で既に毎日使える。** 「誰に何を頼むべきか」は並行実行がなくても
   エージェントを分けた時点で解決する。M3 の山に入る前に実用状態を作り、
   使いながら直せる状況にしておく。
2. **M3 のゴールは「とりあえず2つ同時」に固定する。**
   並行実行は 1つ→2つ が最難関で、2つ→N個 はほぼ同じ。
   最初から「N個を綺麗に管理」を目指すと終わらない。
3. **M3 を越えた直後に、ご褒美として開発室だけドット絵にするのは可。**
   山場の後に達成感がないと M4〜M6 の地味な作業で息切れする。
4. **動いた瞬間にコミットする。** AI駆動開発の最大の事故は
   「動いていたものを大改造で壊す」。

## 9-4 難易度と、正確性をどこで落とすか

本プロジェクトは**個人用ツールであり、正確性より完成と継続を優先する**。
ただし2箇所だけ例外がある。

### 雑でよい（時間をかけない）

見た目、レイアウト、アニメーションの滑らかさ、エラーメッセージの丁寧さ、
テストカバレッジ、リファクタリング。

### 雑にしてはいけない ①：並行実行の状態管理（M3）

「たまに落ちる」では済まない領域。以下は実用不能に直結する。

- 動いているはずのタスクが画面から消える
- 同じタスクが二重に走り、コストが倍かかる
- 完了したのに「実行中」のまま固まる

非同期＋状態管理はバグの原因が見えにくく、「直して」を繰り返すと
別の場所が壊れて泥沼化しやすい。**ここだけは小さく積み、都度動作を確認する。**

### 雑にしてはいけない ②：ツール権限とネットワークバインド

Agent SDK は Bash と Write が使える。雑に作ると実害が出る。

- 0.0.0.0 で待ち受けて外部から叩かれる
- エージェントが想定外のディレクトリを操作する

8章のセキュリティ要件を、**M1 の時点で最初に1回だけ**設定しておくこと。
後回しにする理由がない（コストが低く、事故は重い）。

### 実装上の注意

- **Agent SDK は新しいため、AIが存在しないAPIを生成する可能性がある。**
  公式ドキュメント、または node_modules/@anthropic-ai/claude-agent-sdk/ の
  型定義（.d.ts）を確認してから実装すること。
- 作者は Java 経験者で JS/TS は学習中。
  **async/await と React の状態管理は最初につまずく想定**。
  M3 の難所と重なるため、ここは説明を厚めにするとよい。
- 3回直して直らない不具合は、その部分だけを切り出した
  **最小の再現コード**に落としてから調べる。

## 10-1. 解決済事項

### Agent SDK の認証方式（2026-08-21確認・08-21再訂正）

公式ドキュメント（[Authentication](https://code.claude.com/docs/en/authentication)、[Run Claude Code programmatically](https://code.claude.com/docs/en/headless)）より：

- **Pro/Maxサブスクリプションのログインは、CLI本体だけでなくAgent SDKにもそのまま適用される。**
  公式記載: 「`apiKeyHelper`, `ANTHROPIC_API_KEY`, and `ANTHROPIC_AUTH_TOKEN` apply to the CLI and the surfaces that wrap it, including the VS Code extension, the Agent SDK, and GitHub Actions.」
  → `ANTHROPIC_API_KEY` 等をセットしなければ、認証優先順位の最後（デフォルト経路）としてサブスクのOAuthログインが使われる。**従量課金は不要。**
- **推奨方式**: `claude setup-token` でサブスクに紐づく**1年間有効な長期OAuthトークン**を発行し、`CLAUDE_CODE_OAUTH_TOKEN` 環境変数としてサーバープロセスにセットする。対話ログイン不要で常駐サーバーから安定して使える、CI/スクリプト向けに用意された正規の方法。
  ```powershell
  claude setup-token   # ブラウザで承認 → トークン発行（1回だけ）
  $env:CLAUDE_CODE_OAUTH_TOKEN = "発行されたトークン"
  ```
- **注意点①**: `--bare` モード（CLIの高速起動オプション）は `CLAUDE_CODE_OAUTH_TOKEN` もサブスクのOAuthも読まない。bareを使うなら別途APIキーが必要になるので、このプロジェクトでは使わない。
- **注意点②**: Agent SDK Quickstartの「third party developers may not offer claude.ai login or rate limits for their products」という注意書きは、**他人に配って使わせる製品**が対象。今回は開発者本人だけが使うローカルツールなので抵触しない。
- **トレードオフ**: 課金は増えないが、**普段のClaude Code対話利用と同じレート制限枠を共有**する。M3（複数エージェント同時実行）で普段の利用可能量を圧迫する可能性がある点は運用上留意。
- `CLAUDE_CODE_OAUTH_TOKEN` はシークレットなので `.env` 等に置き、`.gitignore` 済みであることを確認してリポジトリにコミットしない。
